## Fresh source result and the one next probe

[FFmpeg n8.0 `rtmpproto.c`, `rtmp_write`, lines 2910–2928](https://github.com/FFmpeg/FFmpeg/blob/n8.0/libavformat/rtmpproto.c#L2910) switches to nonblocking for a one-byte read, then restores blocking mode before finishing an available RTMP packet. [Its packet reader](https://github.com/FFmpeg/FFmpeg/blob/n8.0/libavformat/rtmppkt.c#L155) reads the remaining header/payload to completion. **Inference:** a fragmented/delayed server control packet can stall a publishing mux even when outbound media is not backpressured. This is a source-supported mechanism, not evidence that the failed soak encountered it. The installed library reports 62.3.100 (**M**`/native-version-receipt.json:1`), matching n8.0's [major](https://github.com/FFmpeg/FFmpeg/blob/n8.0/libavformat/version_major.h#L30) and [minor/micro](https://github.com/FFmpeg/FFmpeg/blob/n8.0/libavformat/version.h#L32); its precise build commit was not established.

**Proposed single bounded native invocation, not executed here:** a synthetic 64×32/libx264 steady-state RTMP control-fragment probe, with a loopback proxy and real MediaMTX. Reuse the real shared engine and public Egress seam, NoOp detector adapters, and generated in-memory credentials. Two conditions in that invocation differ only in control-message fragmentation:

1. Warm up until at least 30 frame writes have received ACKs. At a parsed server-to-client RTMP message boundary, the proxy injects a valid full PingRequest. Keep media forwarding enabled. This control condition must continue receiving frame ACKs; otherwise the probe is invalid.
2. Repeat with the identical message, delivering only its first basic-header byte and withholding the remainder for six seconds. Suspend other server-to-client bytes to avoid corrupting that message; continue client-to-server forwarding. Record injection time, successful ACK count, and the existing numeric worker heartbeat. Do not log payloads, credentials, or URLs.
3. Red predicate: a **write**, after successful warm-up, raises `egress-write-timeout`, heartbeat reports `network-mux` with an active index beyond the last completed index, and the worker is reaped. Startup/cleanup timeout, no successful warm-up, malformed RTMP, or a different operation is a failed/invalid reproduction. Bound the whole probe to roughly 20 seconds and stop/reap only its own resources.

This tests a concrete native path in seconds without reconnects, GPU, decode, or long-duration pressure. It is stronger than another startup-handshake stall, but still an **injected mechanism reproduction**, not historical attribution. If red, inspect that local evidence before proposing a network-path fix; it does not authorize calling rank 1 disproved or claiming the soak repaired. If not red, retain the failed prediction and do not substitute a reconnect fix. The diagnosis skill's already-run red-loop criterion remains **unmet for this historical failure** in this lane.

PyAV 16.0.1 calls `av_interleaved_write_frame` in [output.py](https://github.com/PyAV-Org/PyAV/blob/v16.0.1/av/container/output.py#L409); its output context does not install the input timeout callback ([core.pyx](https://github.com/PyAV-Org/PyAV/blob/v16.0.1/av/container/core.pyx#L225)).
