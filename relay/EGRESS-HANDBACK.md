## Changes and interface notes

`NetworkInput`, stream.py:26–120, is the independently useful portion:

- Queue stays eight events. A full queue no longer blocks `_send` indefinitely:
  it ends the generation, discards queued stale events, emits a `drop`, then
  reconnects. This prevents the old assertion that a socket timeout bounds a
  Python Queue.put wait (it does not).
- Existing five-element event shape is preserved. **Metadata change:** drop
  `value` (tuple slot 2) now holds a fixed reason such as `input-backpressure`,
  `input-open`, `input-decode`, `input-timestamp`, or `input-eof`, rather than None.
  Parent runtime's `else: session.disconnected()` remains compatible.
- Added `error_code` and `failures`; retained `dropped`, `high_water`, `drain`,
  `close`. `dropped` counts discarded queued events, including close cleanup.
- Checks resampled timestamps, flushes the audio resampler at normal EOF,
  clears queued frames and URL reference on successful close. EOF audio flush
  is implemented but not independently exercised by the video-only overload test.
- Real NUT overload check failed on the original queue with dropped=0, and
  passed in runs 5 and 6; it verifies the first drained event is a drop and
  queue high_water <=8, then closes twice and checks no new thread survives.
- Byte size per decoded event is not capped beyond the input's native frame
  size. The bounded claim is eight queued events, not a constant byte budget.

`Egress`, stream.py:123–415, is **experimental and currently failing**:

- Constructor/write/close/count shape is preserved. Public write enforces a
  `PresentedFrame`, correctly sized uint8 BGR/mask, 1600 mono int16 PCM,
  `pts == index/30`, and contiguous indices after the first accepted frame.
  This guards accidental raw-frame bypass; it is not cryptographic provenance.
- Native encode/mux lives in one owned spawned process, fed over an AF_UNIX
  socketpair with synchronous ACKs and one in-flight frame. No background frame
  queue. Per IPC send/receive timeout is five seconds; termination waits .5s,
  then terminate/join 2s, then kill/join 2s. The full operation bound may sum
  send and receive waits plus cleanup; do not claim a five-second total bound.
- Child native crashes cannot make the parent hang indefinitely. Core dumps
  are disabled inside the worker before native work so credentials cannot be
  persisted through a core dump. URL credentials stay in private spawn memory,
  never argv or receipts. The real stalled RTMP test generates its credential
  per run and verifies safe traceback text without including values in assertions.
- **Encoder option extension:** explicit `encoder='libx264'` is accepted for
  CPU transport checks; default remains h264_nvenc. VideoToolbox configuration
  remains present but was not run. Parent must decide whether to retain the CPU
  option after repair; there is no automatic hardware-to-CPU fallback.
- Only `_EncodedOutput.write` submits video pixels to a video encoder; it uses
  `result.index` for video PTS and `index*1600` for PCM PTS, avoiding independent
  float rounding for the two clocks.
- Packet copies now carry PTS/DTS/duration/time_base, keyframe/corrupt flags,
  and side data. This code has not reached a green packet comparison.
- The initial encoder-template archive regenerated incompatible H264 extradata.
  The attempted fix makes the local archive the sole encoder owner, then uses
  decoder templates from its first real video/audio packets for network remux.
  It retains at most 16 startup packets and explicitly copies stream time bases.
  It has a runtime guard against encoder contexts in remux streams.
- Header-only FLV input probing segfaulted the bundled native stack (runs 3/4).
  Final source waits for both actual stream packet types before probing. That
  removes the observed startup crash in runs 5/6 but does not fix later egress.
- Startup ACK now means local encoders initialized. Native network open is
  deferred until enough actual packets exist, possibly during close for a very
  short input. `.count` means acknowledged submitted presentations, not a claim
  every encoded packet has left native buffering. Close must succeed too.
- **Manifest extensions:** `audio_pts_samples` and `audio_samples`. Existing
  PCM/pixel/mask hashes, packed mask, presentation/protection fields remain.
- Fixed error codes never report success on a mux/cleanup failure, but the
  current worker wrapper suppresses the native cause too coarsely for diagnosis.

## Parent audio mapping issue (source-derived, not dynamically reproduced)

Parent `relay/live.py:56–59` reassigns generation/source origin, and `:82–84`
marks a disconnect, but neither invalidates existing audio tags. `:91` selects
samples only by absolute index, without generation. If old-generation audio is
buffered beyond the last submitted video, a new generation can be rebased over
those indices and a tick before replacement audio arrives can emit old audio.
For example, old tags at global sample 49600 (video index 31) can survive a
reconnect whose `session_pts` is 31/30. Its first presentation matches those old
tags until new audio overwrites them. Concrete parent fix to consider: clear
unconsumed audio tags at disconnect/new-generation transition, or tag ring
samples with generation and reject stale tags. Add a parent regression proving
new-generation silence when its aligned PCM has not arrived. I did not edit
shared live.py or assert measured A/V impact.
