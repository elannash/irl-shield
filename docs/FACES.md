# Experimental bystander face protection

This workstream supplies a face lane and benchmark. It does not change the live CLI, engine, stream scheduler, text coverage, Twitch integration or default skin. Root must integrate only after coverage, provider parity and cost evidence are accepted.

`FacePolicy()` requests `bystanders`. `all` masks every detection and `off` explicitly disables face protection. Bystanders exempts **only the largest detected face**, and only when its unpadded, clipped bounding-box area strictly exceeds `selfie_min_fraction` of the frame (default 0.08). Equal-size faces use detector order as a deterministic tie break; at most one is exempt. Smaller faces remain protected even when several exceed the threshold. There is no identity recognition: a nearby stranger, another participant or a face printed on a sign can be exempted instead of the streamer. Use `all` when that heuristic is inappropriate. A detection miss remains a detection miss; a successfully completed empty result does not prove there are no faces.

## Public seam

`YuNetDetector.detect(frame_bgr, source_index, generation)` returns `FaceBatch`, containing source frame index, stream generation, source `(height,width)`, monotonic completion time, tracked `Face(box, confidence, track_id)` records and explicit error state. Boxes are half-open xyxy source-pixel coordinates. `FaceTracker` uses one-to-one IoU overlap only; IDs are `face:<generation>:<serial>`, reset across reconnect generations and never reused for two simultaneous detections. These are geometric tracks, not biometric identity. Missed detections are not extrapolated and are not coverage.

`FacePolicy.plan(shape,index,generation,batch,now=monotonic())` returns a `FacePlan` with coverage, detections, masked track IDs, optional exempt track ID, separate binary uint8 face raster (0/255), face area pixels/fraction and `requires_hold`. Only an exact frame/generation/shape match is accepted. Missing, failed, stale, future-clock, untracked or invalid-geometry coverage yields a full-frame opaque raster, no exemptions and `requires_hold=True`. Completion older than `max_result_age_seconds` (default 0.5) fails closed. Caller must turn construction/metadata exceptions and a missed lane deadline into a source-independent protection slate or the full opaque mask. `off` intentionally needs no face coverage.

This exact-source adapter does not claim asynchronous motion propagation. W1 may provide a separately verified current-source face batch through its generation-aware scheduling seam; an old source result cannot be relabeled as current. Schedule against the unpainted original source before text/face masks, never against an already redacted frame. Do not block the final writer waiting for inference.

`opaque(frame_bgr, face_plan.mask)` returns a new BGR frame, constant inside the face raster and unchanged outside. Padding defaults to 25% of each detected box dimension on every side, clipped outward to the frame. It does not guarantee detection coverage of ears, hair, profile or occluded faces. Face boxes and face area are separate from text boxes and text area. A selfie exemption never clears a text mask. Keep the existing text coverage/real-video/area guards unchanged and audit the actual union of all painted pixels, including faces and overlays. Full-frame fallback is protection, never a usable real-video scoring success.

## Painting and privacy

The accepted face paint in this lane is opaque and source independent inside the exact binary mask. A skin callback may consume face geometry, but **frosted face painting is unqualified**: passing a text OCR check does not demonstrate that recognizable facial structure is hidden. Require its own independent face-privacy evaluation plus a visual verdict before using frosted on faces. The face benchmark's residual face detector is not an identity recognizer and cannot establish anonymity; a missing residual detection is insufficient by itself.

## Optional ORT investigation arm

`YuNetORTDetector` loads the **same bytes**, uses explicit `CUDAExecutionProvider` or CPU provider, FP32 input/output, two intra-op threads, and disables TF32. No FP16 cost assumptions are made for the1080Ti. CUDA is opt-in and requires the root's EX queue. Construction fails if the requested provider is unavailable or silently falls back. Strict CUDA construction sets `session.disable_cpu_ep_fallback=1`; runtime fallback is disabled. The diagnostic arm explicitly permits CPU node fallback, retains it in the receipt, and is not production eligible.

The original graph is opset11,106nodes, inputFP32 `[1,3,640,640]`,12named outputs. Source dimensions are aspect-preserving resized with maximum side640, then zero-padded on the bottom/right to640square. BGR order, raw0..255 values, no RGB swap/mean/std normalization. OpenCV's dynamic adapter instead uses the tight resized rectangle and divisor32 padding; different padding can affect border detections. `parity` compares dynamic OpenCV, square OpenCV, ORT CPU and ORT CUDA separately. Exact model input bytes isolate provider/decode parity. Source-coordinate xyxy boxes are equivalent rectangle quads; no perspective-face quad is claimed.

Predeclared parity tolerances: source-box coordinate max error≤1pixel, score absolute error≤0.001, exact detection counts, exact exemption/masked counts/coverage states, policy mask XOR≤0.001 of frame. Exact XOR counts are also reported; tolerance is not exact raster equality. Full-face/positive/negative controls must detect the intended subjects; two empty/error results cannot earn parity. Unmatched natural-background detections are not automatically false positives.

Actual node placement comes from retained ORT profiling kernel events, including every CPU fallback event and unknown placement. Provider-list presence is insufficient. Empty/mixed/unknown placement fails the strict placement check. ORT provider event durations are not claimed as GPU device time. The separate cost job uses CUDA stream events around synchronous `session.run` and reports device-event elapsed milliseconds including dispatch/transfer interval, CPU process milliseconds and source-frame wall/handoff cost with a real local NVENC30 writer. It does not claim isolated summed kernel compute, native relay cost or full text+face pipeline cost.1080p cost is explicitly upscaled tune content.

## Synthetic benchmark and known limits

Two fictional adult RGBA cutouts were generated by the built-in imagegen tool in this Codex child, with no real-person/reference inputs. `fixtures/faces/assets.json` records exact prompts, model identifier (`not exposed`), SHA256, CC0-1.0 dedication and manually annotated facial rectangles. Rectangles are approximate anatomical placement truth, not model-derived expected outputs. Natural tune backgrounds remain local and must not be shown as public before-view demo footage. The asset cutouts alone contain no readable text/brands/logos/music.

The compositor supplies close-selfie+bystander, two small bystanders, equal large faces, edge entry, and an exhaustive synthetic no-people negative. Root's parity/quality job composites over only the seven hash-pinned tune clips at source indices0/30/60. It rejects source hash drift. No fresh-heldout-v2 media is opened. Two fictional adults do not establish population fairness or street-scene robustness.

Each required face needs successful independent input controls at its known placement and≥99% opaque placement coverage. Judge crops retain35% contextual margin; the positive detection must include the crop center. Residual face detections in required output crops fail privacy. A judge returning no faces fails its positive controls. Every per-frame row reports input controls, residual/unmasked counts, mask area, exemption behavior and false positives for exhaustive synthetic scenes. Natural backgrounds have unlabeled real faces, so false-positive counts are null there and unmatched boxes are separately reported. Off mode is measured but never receives privacy pass. No-people and unannotated full-face controls cannot earn a vacuous privacy pass.

Initial real synthetic receipt `out/w4/synthetic-controls.json` detected both adults and hid them with opaque masks; it also retained an equal-large truth/detector exemption mismatch as RED, not a pass. The first selfie composition did not exercise the large-face exemption; a subsequent source revision increases its synthetic close-face placement and awaits root EX evaluation. Original evidence is preserved. This is a geometry-based heuristic; detector/truth disagreement near a threshold is a real limitation. No threshold/guard was loosened.

The initial explicitly CPU MediaPipe probe unexpectedly initialized an EGL context on the1080Ti before selecting XNNPACK CPU inference. Its original SH command/log/environment intent are retained unchanged, process exited, and it qualifies no timing/cost claim. **All further real MediaPipe calls run through root EX.** Unit tests fake the model boundary and lazily import runtime libraries, so gate discovery never constructs a real model/context.

Source, synthetic policy/decode checks and patch validation are delivered separately from queued real model/CPU-vs-CUDA/NVENC and full-gate evidence. Missing metrics are null. Root must rerun the existing full bench and unchanged text/real-video guards after integration; this independent face scorer cannot certify them.
